## Description

Rebuild the top of Home inside ONE vertically scrolling column (names fixed in `PLAN.md`; the Recent edits strip is T-008's, after this task):

1. "Kanso" as a large title (`headlineLarge`/`Emphasized`, heading semantics) and, under it, "What will you edit today?" (exact text).
2. The hero carousel `home-carousel`: Material 3 `HorizontalUncontainedCarousel` with `flingBehavior = CarouselDefaults.singleAdvanceFlingBehavior(state)` (the default fling does not snap), `rememberCarouselState { 4 }`, a fixed height (192 dp, never below 176; give the carousel `Modifier.height(...)` inside the scrolling column), banners in order Remove background, Enhance, Retouch, Artistic. Each banner `home-banner-<TOOL>` is a `Card(onClick)` with `Modifier.maskClip(shape)` built from the scheme's container colours (`primaryContainer`, `secondaryContainer`, `tertiaryContainer`, ... with their `on...` roles; no bitmap art, no fixed colour), holding the tool's label, a one-line description (`maxLines = 1`, new string per tool), the tool's icon drawn large (`Icon(painterResource(tool.iconRes), null, Modifier.size(88.dp))`, tag `home-banner-<TOOL>-icon`) and a small pill `Button(shapes = ...)` "Try now" (`home-try-<TOOL>`, with the tool's name in its content description so four buttons do not read the same). The banner and the button both call `onToolClick(tool)`. Do NOT use `Modifier.carouselParallaxScrollEffect` (experimental). Page dots under it (`home-carousel-dots`, dots `home-carousel-dot-<i>`): not tappable, the current one marked (`selected`/`stateDescription`) from `state.currentItem`; no auto-advance. KDoc explains "carousel" and names the function used (DoD 37).
3. Two pill buttons side by side: "Edit" (`home-pill-EDIT`, wraps its content) and "Remove background" (`home-pill-REMOVE_BACKGROUND`, `weight(1f)`), small `Button(shapes = ...)` with the tool icon, both calling `onToolClick`.
4. `contentPadding: PaddingValues = PaddingValues()` on `HomeScreen`/`HomeContent`, applied as the bottom content padding (T-001 added it; the host passes the floating bar's clearance).

Row heights (the DoD 6 budget, 24 dp spare on 360x780 with a 48 dp navigation bar once T-008 adds the strip): status inset 24, title 48, greeting 28, gap 16, carousel 192, gap 12, dots 8, gap 16, pills 48. Do not change them.

`HomeContent(state, onToolClick, modifier, contentPadding)` is the stateless screen; `HomeUiState` holds the carousel tools (Remove background, Enhance, Retouch, Artistic) and the pill tools (Edit, Remove background) as plain lists; `HomeViewModel` keeps its one `state: StateFlow<HomeUiState>`. Delete everything R4 and R5 name (`OpenPhotoButton`, `ToolGroup`, `GroupHeader`, `ToolCard`, `HOME_OPEN_PHOTO_TAG`, `homeToolTag`, `aiTools`, `editTools`, `onOpenPhoto`, `ic_add_photo_alternate`'s use); keep `HOME_SCREEN_TAG`. Preview `HomePreview` (kept name) and, if you split files, one preview per file.

**Tests (each Android version its own `@Test`).** `HomeScreenTest` (hosted `HomeContent`, the phone: the order of title, greeting, carousel, pills by `positionInRoot`; four banners in order, each with label, description, icon, "Try now"; the dots; a left swipe settles on banner 2 with its "Try now" wholly on screen and the dots marking 2; 10 s of clock time with no input leaves banner 1), `HomeViewModelTest` (state lists), `LaunchTest` (`home-screen`, "Kanso", `nav-bar` with Home selected; separate `@Test` for SDK 27, 30 and 35; no "Open a photo"), `NavigationTest` and `PhotoToToolNavigationTest` as above (the whole-app tests swap the edits source and the photo source BEFORE `ActivityScenario.launch` with `createEmptyComposeRule()`; find Home's nodes by tag, never by text; the carousel is lazy, so swipe `home-carousel` first). `HomeTaps.openToolGallery` is what every other test uses to reach a tool gallery.
