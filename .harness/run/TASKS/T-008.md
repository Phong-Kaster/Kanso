## Description

Write the transition specs the app hands to `NavDisplay`: a push (`transitionSpec`), a pop (`popTransitionSpec`) and the back-gesture pop (`predictivePopTransitionSpec`), built from `MaterialTheme.motionScheme` (spatial specs for movement, effects specs for fades), so the screens slide and fade with the Expressive spring. The functions take the motion scheme (or the specs) as parameters so the file holds no `@Composable` text. Explain `transitionSpec`, `popTransitionSpec`, `predictivePopTransitionSpec` and predictive back in plain English where first used (DoD 30).

`NavTransitionTest` hosts `NavDisplay` directly with these specs (no Koin, no `MainActivity`, so it does not depend on the Iteration's wiring): paused clock; one frame after a push both screens are composed and 2 000 ms later only the new one; the same for a pop; a normal Back completes the pop. A second pass with `Settings.Global.ANIMATOR_DURATION_SCALE` 0 only after a control assertion shows the Robolectric host carries the setting into Compose's `MotionDurationScale`; if it does not, the test states so (DoD 13: "not driven by machine" is not a failure).

After the Worker, the Iteration wires `KansoNavDisplay` and the manifest flag and runs the whole suite: `Espresso.pressBack()` tests (`NavigationTest`, `PhotoToToolNavigationTest`, `ThemeModeSettingsTest`, `ThemeColourSettingsTest`, `ScreenshotTest`) may react to the flag; the Phase 1 spike recorded what to expect.
