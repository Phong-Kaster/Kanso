## Description

- **The source** (`PLAN.md` "Names fixed"): `interface SavedPhotoSource { suspend fun savedPhotos(): List<Photo> }` and `MediaStoreSavedPhotoSource(context, sdkInt = Build.VERSION.SDK_INT)`. Photos in Kanso's own `Pictures/Kanso`, newest first by the file's last-changed time (`DATE_MODIFIED`, the field the gallery uses), each a `content://` Uri (`ContentUris.withAppendedId`). Android 10+: filter on `RELATIVE_PATH = 'Pictures/Kanso/'` (the saver's constant is private: write the literal). Android 8.1 and 9 (API 27, 28): no `RELATIVE_PATH`; filter on the file path (`DATA LIKE '%/Pictures/Kanso/%'`) and treat the missing read permission (`SecurityException`) as "nothing readable". Any exception gives an empty list; it never asks for a permission, never writes, runs on `Dispatchers.IO`. Read `data/photo/MediaStorePhotoSaver.kt` (what is saved and where) and `data/media/MediaStorePhotoSource.kt` (how the gallery maps rows; the gallery's real query is in `core/gallery/.../MediaRepository.kt`).
- **The screen** in `ui/myedits/` (three files, one UiState and one ViewModel; `ui/home/HomeUiState.kt`'s KDoc explains the pattern): `MyEditsViewModel(savedPhotos, probe)` with one `state: StateFlow<MyEditsUiState>` and `fun refresh()`; `MyEditsUiState` says loading, empty or the photos; `MyEditsScreen(viewModel, onPhotoClick: (String) -> Unit, modifier, contentPadding: PaddingValues = PaddingValues())` calls `viewModel.refresh()` each time it enters the composition (a tab's screen is recreated when you come back, so a photo just saved is always there) and `MyEditsContent(state, onPhotoClick, modifier, contentPadding, thumbnail: @Composable (Photo, Modifier) -> Unit = ...)` is the stateless screen the previews and tests use, with `PhotoThumbnail` as the default thumbnail and a coloured-box stand-in in previews (the pattern is `GalleryContent`, `GalleryScreen.kt:271-272, 827-862`: a preview never loads a real Uri). A `LazyVerticalGrid` of rounded tiles (`my-edits-tile-<i>`, `MaterialTheme.shapes.large`), reading order = newest first, each tile with the content description from `R.string.my_edits_photo_description` ("Edited photo, %1$s" with the saved date and time; no visible text, Q9; define it in `strings_myedits.xml`: T-008 reuses it); tags `my-edits-screen`, `my-edits-grid`; no title (the bar names the tab); the grid applies `contentPadding` as its content padding (the host passes the bar's clearance; do NOT call `tabBarClearance()`); empty state `my-edits-empty` with a short message (new string); loading shows at least six `my-edits-skeleton-<i>` blocks the size of a tile and ONE content description on the grid saying photos are loading (new string), no spinner and no `ProgressBarRangeInfo`. KDoc explains `LazyVerticalGrid` where it is first used (DoD 37). Previews `MyEditsPreview`, `MyEditsEmptyPreview`, `MyEditsLoadingPreview`, each light and dark.
- **Skeletons** (`ui/common/SkeletonBlock.kt`, one file, its own light and dark previews, previews NEVER animate): `LocalSkeletonPhase` (default a still frame), `SkeletonBlock(shape, modifier)` painting `surfaceContainerHigh` with a moving band of `surfaceContainerHighest` read in the draw phase (`drawWithCache` or `drawBehind`, no recomposition per frame), and `ProvideSkeletonPulse(pulsing: Boolean = true, content)` that provides an animated phase from `rememberInfiniteTransition` when `pulsing` (Compose animation APIs only; never the word "shimmer" in `app/src/main`, DoD 20(a)); the preview in this file calls `ProvideSkeletonPulse(pulsing = false) { SkeletonBlock(...) }` so `PreviewCoverageTest` counts both composables as covered without a preview that animates forever (that hangs `PreviewsRenderTest`, PROJECT.md). `MyEditsScreen` wraps its content in `ProvideSkeletonPulse()`; `MyEditsContent` and every preview use the still default.
- **Tests (each Android version its own `@Test`):** `MyEditsViewModelTest` (newest first; refresh picks up a new photo; an empty source; a source that throws gives empty), `MyEditsTest` (hosted `MyEditsContent`: 40 tiles in reading order, rounded, content descriptions, scroll reaches the 40th, empty message, skeletons while the fake holds reads and none after release, no spinner), `EditsSourceTest` (DoD 32 at SDK 27, 30 and 35 against `RecordingMediaProvider`: a registered `media` provider backed by an in-memory table that applies the selection and the sort it is given and accepts inserts, so it can also record what `MediaStorePhotoSaver` saves; 5 photos in `Pictures/Kanso` and 3 elsewhere; exactly the 5, newest first, `content://` Uris; no insert/update/delete recorded by the source's reads; at SDK 27 the path filter; missing read access gives empty; a photo saved by `MediaStorePhotoSaver` at SDK 35 is then returned first), `MyEditsScreenshotTest` (pictures `28_my_edits_light` to `33_my_edits_loading_dark` named in `PLAN.md`: populated and empty at SDK 30, loading at SDK 35 with the clock paused before `setContent`, light and dark; the Iteration records them). `FakeSavedPhotoSource` has `holdReads()` / `releaseReads()` like `FakePhotoSource`. Whole-app tests of this screen (a tab tap, the viewer) belong to T-004 and T-005.
