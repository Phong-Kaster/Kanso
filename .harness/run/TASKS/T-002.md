## Description

`SettingsViewModel`'s custom-colour function currently writes DataStore on every `onColorChanged`. Debounce inside the ViewModel (about 300 ms of quiet; injectable dispatcher/clock for tests) so a drag produces one write holding the last colour. The picker exposes no drag-end callback, so keep the change out of `SettingsScreen.kt`. Existing tests (`ThemeColourSettingsTest` "applies at once", `ThemeColourRestartTest`) must still pass. No live preview during the drag (A-003). When the ViewModel clears, flush the last pending colour: `viewModelScope` is already cancelled in `onCleared`, so the flush must run in a scope that outlives the ViewModel (the repository's own scope, as Run 1's store does).

## Acceptance

DoD 29. 50 colour changes 16 ms apart give 0 writes; after the settle interval exactly 1 write of the last colour; flush on clear.
