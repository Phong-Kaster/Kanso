## Description

PRD item 9. Today the field reads the typed text with `toLong()` (base 10, no alpha) inside `tryWithoutCatch` (which swallows exceptions), and its filter drops lowercase letters (`HSVColorPicker.kt:66-71`): typing `2E7D32` saves `000002`. The fix: keep only hex digits in either case (`0-9`, `a-f`, `A-F`), upper-cased in the field, at most 6; apply ONLY when exactly six digits are present: parse with `toLong(16)`, OR in `0xFF000000`, make `Color(argb)`, set `colorPickerValue = HSVColor.from(color)` for the picker's own bars and call `updatedOnColorChanged(color)` with that exact colour (do NOT pass `colorPickerValue.toColor()`: the HSV round trip can move a channel by one; `HSVColor.toHex()` drops alpha, `HSVColor.kt:33-37`). Fewer than six digits changes nothing and calls nothing. Dragging the bars still updates the field with the dragged colour's code, as today. The engine compiles against Compose UI 1.8.2 (PROJECT.md). Comment the change in plain English: the code is read in base 16 and made opaque (DoD 37).
