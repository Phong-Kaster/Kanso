## Description

Filed by the Verifier (Iteration 13). A fresh-context Capable reader compared README, `docs/features/edit.md`,
`docs/features/tool-screen.md` and ADR-004 with the code (DoD 40's pre-check). DoD 38 and 39 hold and every
named path exists, but two sentences are false and six say more than the code. Fix each so it says what the
code does; change no code.

1. **False.** `README.md:129-130`: "All of this, and the row and the sheets, runs on the main thread as Compose
   draws; no pixel is computed." The cropper's sticker bake copies the photo and draws each sticker picture on
   the main thread inside composition (`ui/tool/components/EditCropper.kt:98-108, 220-246`); README's own step 10
   (lines 279-280) says so.
2. **False.** `docs/features/edit.md:160-161`: "The cropper, the sheets and the row all run on the main thread,
   as Compose draws; none of them touches pixels." Same code; `edit.md:151-152` already says it.
3. **Imprecise.** `README.md:221-223`: `editProcessorFor(context)` "is used by the cropper, the sheets, the
   sticker taps and Done". The cropper only passes it through `commitCrop` (`ToolScreen.kt:279`); it draws its
   stickers with its own `DrawableStickerPictures` (`EditCropper.kt:105`).
4. **Imprecise.** `README.md:211-212`: "so does any other way of closing it (`closeTool`)". `closeTool` is never
   reached for the Stickers sheet (`ToolViewModel.kt:629, 637`: Stickers goes to `cancelStickers`).
5. **Imprecise.** `README.md:281-283`: out of memory gives the "too large to edit" message. Out of memory while
   decoding one sticker picture returns null (`DrawableStickerPictures.kt:41-43`) and that sticker is silently
   skipped in Done (`EditProcessor.kt:163`); only out of memory elsewhere in the render gives the message.
6. **Imprecise.** `README.md:181` and `edit.md:190`: a failed filter preview "shows the photo without the filter".
   `filterPreview` becomes null (`ToolViewModel.kt:809`), the card draws the original (`PhotoCard.kt:166`) and
   the resting stickers are not drawn either.
7. **Imprecise.** `edit.md:411-412`: "A sticker's width stays between 5 and 100 percent of the shown width." The
   clamp runs only during a gesture or handle pull (`StickerGestures.kt:175-178`, `StickerOverlay.kt:177-178`);
   a later tighter crop can push it past 100 percent.
8. **Imprecise.** `edit.md:213` (mermaid): "publishSession: selectedStickerKey = the new sticker". `publishSession`
   only prunes the selection; `addSticker` sets the key afterwards (`ToolViewModel.kt:399-400`).
