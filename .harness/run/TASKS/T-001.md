## Description

Make the tool screen able to host a real edit.

- A `ToolProcessor` seam: suspend, runs off the main thread, reports progress 0..1, returns an edited Bitmap or a typed failure (OutOfMemory, NoSubject, NoFace, ModelUnavailable, Other). `CancellationException` is never a failure.
- `ToolViewModel` keeps the working copy, a history stack (undo back to the original), Processing/progress, failure state and the edited bitmap. `ToolUiState` gains defaulted fields only (tests build it by name); new ViewModel constructor parameters go last with defaults.
- `ToolScreen` shows the edited bitmap, a progress indicator (Compose animation APIs, tag `tool-progress`), an Undo control (`tool-undo`) and a per-tool panel slot (`edit-panel`, `cutout-panel`, `enhance-panel`, `retouch-panel`, `artistic-panel`); a tool not yet built shows an empty slot, never the old message.
- `PhotoSaver` gains a bitmap entry point: JPEG q95 for opaque, PNG for a bitmap with alpha; extension, MIME and the API 27-28 scanner MIME follow the format. Save saves the edited bitmap; an unedited photo still goes through the original-bytes path. Share sets the MIME from the file.
- Remove `EditorPanel` and the five `editor_panel_*` strings; rewrite ToolScreenTest's later-run checks.
- Record every test change with its reason in `.harness/run/evidence/test-edits.md`.
- Working-size caps are constants here (Q3: Remove background 2000, Enhance 512, Retouch 2000, Artistic 1024).
