## Description

Phase 1 of the PRD: the sticker model, the undo actions and `EditProcessor`'s new first step. Implement exactly
the contracts in PLAN.md "Contracts fixed here" (Data): `Sticker`, `EditSettings.stickers` / `canAddSticker` /
`MAX_STICKERS = 20`, `isNeutral()` (no tool) gaining `&& stickers.isEmpty()`, `EditSession.addSticker`,
`deleteSticker`, `duplicateSticker(key, newKey, offsetX, offsetY)`, `flipSticker`, the `StickerPictures` fun
interface with a do-nothing default in `EditProcessor`'s constructor, and the drawing of each sticker after the
crop rectangle is cut out, shifted by its offset (own bounding-box bitmap per sticker, Canvas + Matrix for size,
mirror and turn, alpha-blended into the crop pixels, recycled) - before turns, flips, filter and sliders.
No UI caller exists until Phase 2; that is the PRD's commit order. KDoc on every declaration, teaching what a
sticker is and why it is drawn first. No `@Composable` text in these files.

README "How each editing feature works → Edit" and `docs/features/edit.md` state the new render order
(stickers, crop, turns, flips, filter, sliders) - nothing more yet.

## Acceptance

- `EditSession`: add, delete, duplicate and flip each push exactly one undo entry; a gesture through
  `preview`/`commit` with 50 moves pushes exactly one and its undo restores the pre-gesture settings; one that
  ends where it began pushes none; at 20 stickers an add and a duplicate leave the session unchanged; a mixed
  sequence (crop, add, filter, drag) undoes in reverse order (DoD 12, 13).
- `EditProcessor` with `SolidStickerPictures`: a crop through a sticker keeps only its kept part; a crop that
  excludes it leaves no sticker pixel; a quarter turn plus a horizontal flip moves the sticker's pixels with the
  photo; a full-strength filter and raised brightness colour the sticker pixels; output size is unchanged by
  stickers; a 1-px checkerboard sticker mapped 1:1 lands pixel for pixel (± 1); no stickers gives exactly the
  old pixels (the existing `EditProcessorTest` passes untouched) (DoD 15, 16, 18).
- `EditSettings` holds no selection field (DoD 21).
