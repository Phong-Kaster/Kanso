## Description

Gather RGB, HSL and Curves under one entry, **Colour**, on the Edit screen's tool row, with Beautify's
two-level pattern. Contracts fixed by the plan (do not re-decide them):

- **Model.** `EditTool` is unchanged (10 cases, same order). `EditToolGroup` is an enum with one case
  `COLOUR` whose `tools` are `[RGB, HSL, CURVES]`. `EditRowEntry` is a sealed interface with `Group(group)`
  and `Single(tool)` and a `TOP_ROW` list: Crop, Rotate, Adjust, Group(COLOUR), Filters, Stickers, Text,
  Date. Neither file references a resource.
- **Shared pieces** (in `ui/tool/component/`, one per file): `GroupBackEntry` — Beautify's Back entry
  (`ic_arrow_back`, `R.string.back`), taking `enabled`, `onClick`, `modifier` and its **test tag as a
  parameter**, with Beautify's `BackEntryPreview` moved into it; `GroupRowTransition.kt` — Beautify's
  slide `transitionSpec` as a function (not a composable, no preview). `BeautifyToolRow` uses both, and
  keeps its tags (`beautify-back`), its Back at the right, and its pixels (pictures 47/48).
- **Layer 1** (`EditToolRow`): the `LazyRow` (`EDIT_TOOL_LIST_TAG`) over `EditRowEntry.TOP_ROW`; the
  Colour entry is an `EditToolEntry` labelled `edit_colour_group` = "Colour" with `ic_palette`, tag
  `edit-group-COLOUR`, dot tag `edit-group-dot-COLOUR`, dot shown when any of its tools is not neutral.
  RGB's icon becomes the new drawable named in D-001. Compare stays pinned at the right after the divider.
- **Layer 2** (`EditColourGroupRow`, `internal`, its own `@PreviewLightDark`): `GroupBackEntry` pinned
  at the **left** (tag `edit-group-back`), then a `LazyRow` tagged `EDIT_TOOL_LIST_TAG` of RGB, HSL,
  Curves as `EditToolEntry` with their existing `edit-tool-<NAME>` / `edit-tool-dot-<NAME>` tags, then the
  divider and Compare pinned at the right. `EDIT_TOOL_ROW_TAG` stays on the outer row on both layers.
- **State.** "Colour open" is `rememberSaveable` local to `EditToolRow` (Beautify's precedent,
  `BeautifyPanel.kt:114`; deliberately not in `ToolUiState`, so no ViewModel, UiState or `ToolScreen.kt`
  change). Layer 2 is shown when that flag is set **or** the open tool is RGB, HSL or Curves. The flag is
  lost when Stickers, Text or Date replace the row — harmless, they are layer-1 tools; say so in KDoc.
- **Closing without a new callback.** The row has only `onOpen(EditTool)`, which toggles
  (`ToolViewModel.openTool`). Tapping Colour while a non-colour tool is open calls `onOpen(openTool)` to
  close it, then shows layer 2. Back calls `onOpen(openTool)` if a colour tool is open, clears the flag
  and shows layer 1. Do **not** add an `onClose` parameter (that would pull `EditBottomBar.kt` and
  `ToolScreen.kt` into scope).
- **Enabled.** While Compare is on, Colour, Back and the three tools are disabled; Compare stays enabled.
- **Motion.** The switch between layers uses `AnimatedContent` with the shared transition.
- **Tests.** `ColourGroupTest` covers DoD 1-8 and the one-line "Colour" label (11). Existing tests that
  scroll the flat row to RGB/HSL/Curves learn to open Colour first: put one helper in
  `ToolRowScrolling.kt` (`scrollToolRowTo` opens Colour for those three) so most callers need no edit.
  Edit `HslSheetTest`'s "HSL sits between RGB and Filters" to the new truth (HSL between RGB and Curves on
  layer 2). `ToolScreenshotTest`: `openSheet` opens colour tools through Colour; the two
  `edit_tool_row_hsl_*` tests (pictures 83/84) show the Colour group; add four tests for pictures 101-104
  (DoD 11). Never touch the VM-level tests listed in DoD 9 or `BeautifyToolTest`.
- **Docs** (slice D): README's tool-row description, the RGB/HSL/Curves rows of "Editing features" and
  their "end to end" sections ("reached through Colour", file paths), "Known limits" about row length;
  the same in `docs/features/edit.md` and `docs/features/tool-screen.md`; a line in
  `docs/features/beautify.md` that its Back and slide are now shared pieces; `EditTool.kt`'s KDoc no
  longer says the case order is the row's order.
