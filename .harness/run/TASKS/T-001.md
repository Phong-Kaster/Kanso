## Description

Move the toolchain to AGP 9 and change nothing a person sees:

1. **Wrapper first, on the old Gradle.** `./gradlew wrapper --gradle-version <v> --distribution-type bin --gradle-distribution-sha256-sum <sum>` where `<v>` is the version AGP 9.4.1 needs (AGP 9.4's notes give 9.6.0 as the floor; use the number AGP's own error names if it is higher) and `<sum>` comes from `curl -sL https://services.gradle.org/distributions/gradle-<v>-bin.zip.sha256`. Run `./gradlew wrapper ...` once more under the new Gradle to refresh `gradle-wrapper.jar` and the scripts. Gradle 8.14.3 cannot configure AGP 9.4.1, so do this before step 2.
2. `agp = "9.4.1"` in the catalog (the newest stable 9.x on Google Maven, 2026-10-09).
3. Remove `org.jetbrains.kotlin.android` (alias `kotlinAndroid`) from the catalog, the root `build.gradle.kts` and every module: AGP 9 compiles Kotlin itself (built-in Kotlin). `kotlin { compilerOptions { jvmTarget ... } }` stays; the engine modules already use it, not `kotlinOptions`. The Compose compiler plugin and the serialization plugin stay (compatible with built-in Kotlin). Do not set `android.builtInKotlin=false`, `android.newDsl=false` or any other `android.*` property to hold an AGP 8 behaviour. Check `./gradlew -q buildEnvironment`: `org.jetbrains.kotlin:kotlin-gradle-plugin` must resolve to the catalog's `kotlin` (2.3.20 in this Phase); if built-in Kotlin took a lower one, put the plugin on the build-script classpath (the one exception of DoD 14).
4. **A Capable Worker** (scope: the eight `core/*/build.gradle.kts` and `opencv/build.gradle`) adapts them only as far as the build requires. Give it the traps of PLAN "Known Risks" (a to d for OpenCV; the NDK; `mlModelBinding`; the Compose compiler flag; duplicate namespaces) and, each round, the AGP 9 error text (§6.7). Where the AGP 9 error text is unclear, look the symbol up with the `library-docs` skill before the second attempt and put the excerpt in the Brief.
5. `app/build.gradle.kts`: `compileSdk` 37 (fix the comment above it: it says 36 because of Navigation 3 and lifecycle 2.10, which is no longer the reason); `targetSdk` stays 36, `minSdk` 27; the three debug ABIs stay.
6. Libraries stay exactly as at base: BOM 2026.05.00, nav3 1.1.7, lifecycle-nav3 2.10.0, material3 1.3.2 (catalog), CameraX 1.6.2, Roborazzi, Robolectric, ComposablePreviewScanner, **Kotlin 2.3.20** (it moves in Phase 2; if AGP 9.4.1 or a plugin refuses it, move it only as far as needed and PROJECT.md records the error that forced it).
7. **The NDK.** Compare the new debug APK's native libraries with `.harness/run/evidence/base-native-libs.txt` (DoD 15). If they differ, AGP 9.4.1's default NDK changed: set `ndkVersion = "27.0.12077973"` (the base's) in `opencv/build.gradle` and `app/build.gradle.kts` and rebuild, or record in PROJECT.md why each difference is harmless.
8. Kotlin sources, test sources and baselines are not touched.
9. Update `.harness/knowledge/PROJECT.md`: the "Engine build style" line, the "Version pins below latest stable" line (AGP and Gradle only at this step), the wrapper version (base is 8.14.3, not 8.13), the verified command set, and any Constraint the migration discovers (for example "never apply `org.jetbrains.kotlin.android` or set an AGP opt-out flag", and the DSL traps found).
