## Description

The navigation shell, as stateless pieces plus plain back-stack functions. Names are fixed in `PLAN.md` ("Names fixed by the plan"); use them exactly. Read `.harness/knowledge/api-digest.md` sections J, N, O, P first.

- `KansoTab { HOME, MY_EDITS, SETTINGS }` with `labelRes`, `iconRes` and the tab's `NavKey` (`Home`, `MyEdits`, `Settings`). `MyEdits` is a `@Serializable data object ... : NavKey`, written like `Settings.kt`. New strings in `strings_tabs.xml` with NEW names (`tab_home`, `tab_my_edits`, `tab_settings`); the Camera button's description is the existing `R.string.tool_camera`. The My edits icon is `R.drawable.ic_photo_library` (the Iteration fetches it before you start; `ic_home`, `ic_settings`, `ic_photo_camera` exist).
- `KansoTabBar(selected, onTabSelected, onCamera, modifier)` (stateless, own file, `KansoTabBarPreview` in light and dark from sample data; the preview also calls `tabBarClearance()`, because `PreviewCoverageTest` counts a composable as covered only when a preview in the same file reaches it): one `Row` holding a pill-shaped Material 3 `ShortNavigationBar` with three `ShortNavigationBarItem`s (icon over label, `iconPosition = Top`) and, beside it, a round `FilledIconButton(shapes = IconButtonDefaults.shapes())` 64 dp (`nav-camera`, the Camera icon, content description "Camera", no visible text). The bar is a `Surface` with no `shape` parameter: make it a pill with `Modifier.shadow(...)` then `Modifier.clip(CircleShape)` in its modifier, and pass `windowInsets = WindowInsets(0, 0, 0, 0)` so the bar does not grow by the inset; pad the outer Row by `WindowInsets.navigationBars.union(WindowInsets.systemGestures.only(WindowInsetsSides.Bottom))` through `windowInsetsPadding` plus 16 dp (PROJECT.md bottom-bar Constraint). Colours (Q22, all from `MaterialTheme.colorScheme`): container `inverseSurface`, content `inverseOnSurface`; selected indicator (the pill) `inversePrimary`, selected icon `inverseSurface`, selected label `inversePrimary`, unselected icons and labels `inverseOnSurface`. Use `selectedTextColorTopIconPosition`: the overload with `selectedTextColor` is hidden and does not compile. Icons carry `contentDescription = null` (the label names the tab). Tags: the bar `nav-bar`; each item `nav-tab-<TAB.name>` (put the tag in the item's `modifier`, which lands on the selectable `Role.Tab` node); each icon `nav-tab-<TAB.name>-icon`; the button `nav-camera`. The camera button is NOT inside `nav-bar`. At 320 dp wide (the default Robolectric screen) the three items plus the button must fit; test it. KDoc says what a tab bar is, why the bar is the inverse of the screen, and why it clips to a pill (DoD 37: the file mentions "tab" and `inverseSurface`).
- `@Composable fun tabBarClearance(): Dp` (same file): the bottom space a tab screen leaves for the floating bar (64 dp bar + 16 + 16 + the larger of the navigation-bar inset and the bottom system-gesture inset). Only the Iteration's nav host calls it.
- `KansoTabShell(showBar, selected, onTabSelected, onCamera, modifier, content)` (stateless, own file with `KansoTabShellPreview`): a `Box` drawing `content()` and, aligned at the bottom, the bar while `showBar` is true AND no keyboard is open (`WindowInsets.isImeVisible`, an opt-in layout API; Q13), animated in and out with `MaterialTheme.motionScheme` effect specs; a hidden bar is not in the tree (`assertDoesNotExist` or not displayed, DoD 1). Explain in KDoc how the tabs live on the Navigation 3 back stack (the host decides `showBar` from the top key).
- `kansoTabEntryMetadata(motionScheme)` in `KansoTabTransitions.kt`: the per-entry `NavDisplay.transitionSpec` and `popTransitionSpec` metadata (digest section P) that return a fade-through only when BOTH the initial and the target scene are tab keys (`isTabKey`) and `null` otherwise, so every other move keeps `KansoTransitions.kt` (not edited: it is shared). `NavTransitionTest` gains a tab case: a hosted `NavDisplay` with Home and Settings entries using this metadata, driven frame by frame with the clock paused: between the two tabs the incoming screen does not slide (its left stays at 0 while it fades), and a push to a non-tab key still slides.
- `BackStackActions.kt`: `isTabKey(key)`, `MutableList<NavKey>.selectTab(tab)`, `MutableList<NavKey>.replaceWithGallery(tool)`, `MutableList<NavKey>.closeToHome()` exactly as `PLAN.md` defines them, each with KDoc explaining the move on the back stack. `BackStackActionsTest` is a plain unit test of them over a plain list (Home at the bottom, `Gallery(tool)`, `ToolPhoto(...)`, `MyEdits`, `Settings`).
