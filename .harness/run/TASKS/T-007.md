## Description

`PhotoSaver` interface + MediaStore implementation: Android 10+ inserts a row (`RELATIVE_PATH=Pictures/Kanso/`, `DISPLAY_NAME=Kanso_<yyyyMMdd_HHmmss>.jpg`, `MIME_TYPE=image/jpeg`, `IS_PENDING` 1 then 0) and writes through the resolver; Android 8.1-9 writes `Pictures/Kanso/` under the public directory and runs `MediaScannerConnection.scanFile`, after asking `WRITE_EXTERNAL_STORAGE` at Save time (denial shows a message, writes nothing). Upright (A-001): a photo with no rotation is copied byte for byte; a rotated photo is decoded at full size, rotated, re-encoded at quality 95; if that runs out of memory, copy verbatim keeping its EXIF tag and tell the user. The original is never opened for writing. The tool screen's Save action calls it off the main thread, shows progress/failure, and on success calls `onSaved(uri: String)`. Explain MediaStore and scoped storage where first used.

Reuse T-003's permission gate in `ui/permission/` for the API 27-28 write request; that folder is not in this scope, so any change to it goes through the Iteration. The decode is behind an injectable decoder seam so a test can make it throw `OutOfMemoryError`; file names are `Kanso_yyyyMMdd_HHmmss.jpg` with a `_<n>` suffix when that name exists (legacy path must not overwrite). Save action keeps clear of the gesture area. Orchestrator wires before dispatch: manifest `WRITE_EXTERNAL_STORAGE maxSdkVersion=28`, Koin binding, strings.
