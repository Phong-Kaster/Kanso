## Description

Found by the fresh-context review of Phase 3 (blocking finding B1, DoD 2). The Custom row's swatch must show "the colour of the last custom seed (the Kanso blue seed on a fresh install)". T-007 draws `Color(selected.seedArgb)` only while Custom is selected and `KANSO_BLUE_SEED` otherwise, because `SettingsUiState` holds just the selected colour. But the repository keeps the last picked seed under `theme_colour_seed` when Kanso blue or wallpaper is chosen ("so picking Custom again starts from it", `SettingsRepository.kt:76-77`, `chooseCustomThemeColour()`).

Failure to remove: pick Custom, drag the picker to green, tap Kanso blue: the Custom swatch shows `#1A73E8` (the seed), then tap Custom and the app turns green, so the swatch named the wrong colour.

- Expose the stored seed: a `Flow<Int>` in `SettingsRepository` (the stored `theme_colour_seed`, else the Kanso blue seed's ARGB), a new `SettingsUiState` field with a default value (so every existing `SettingsUiState(themeMode, themeColour)` call, including previews and tests, still compiles) and `SettingsViewModel` combining it into its one `state` flow (the initial value before the file is read stays System plus the default colour plus the Kanso seed). Keep `SettingsRepository(…, sdkInt)`, `defaultThemeColour`, `SettingsViewModel.onWallpaperChosen` and the stored names exactly as they are (PROJECT.md Constraints). `ScreenStateTest` rules still apply: the ViewModel exposes exactly one `StateFlow<SettingsUiState>`, the UiState file has no `var` and no `Mutable…`.
- `SettingsContent`'s parameter list stays as it is (T-011 hosts it): the swatch reads the colour from the state it already receives.
- Test, in `ThemeSwatchTest` (SDK 35, the way T-007's tests drive Settings): (1) choose Custom, set the seed to a colour that is not the Kanso blue seed (through the ViewModel/repository as `ThemeColourRestartTest` or `CustomColourDebounceTest` does, not by typing into the picker's hex field), wait for it to be saved; (2) tap the Kanso blue row; (3) the swatch `theme-colour-custom-swatch`'s centre pixel is that colour, not the Kanso blue seed (within +-2 per channel). Also a repository test: after `chooseCustomThemeColour` and a seed write then `chooseKansoBlue`, the new flow still reads the seed; on an empty store it reads the Kanso blue seed.
