## Description

Add `OneTypePerFileTest`, a plain JUnit test (no Robolectric) beside `KdocCoverageTest`, following the repository's convention for
codebase-wide source scans (`KdocCoverageTest.kt:108-119`, `PreviewHygieneTest.kt:392-403`): its own private
`findAppSourceRoot()` that walks up from `user.dir` and accepts `src/main/java` or `app/src/main/java` once `com/phongkaster/kanso`
exists under it; files found with `walkTopDown()` filtered to `.kt` and sorted by path; problems reported as
`path:line message` with `invariantSeparatorsPath`; the test fails if it finds no files. It scans **both** `app/src/main/java`
and `app/src/test/java`, and never reaches `reference/` or `core/`.

**The rule.** A file may hold at most one top-level type, and a file holding one must be named after it (`Foo.kt` for `Foo`).
A file holding none (a screen's composables, `AppModule.kt`, `KansoTheme.kt`) is fine, and top-level functions, properties and
constants may sit beside the one type. A top-level type is a `class`, `interface`, `fun interface`, `object`, `data object`,
`enum class`, `annotation class`, `sealed` or `data` or `value` or `inner`/`open`/`abstract` class, with any visibility modifier
(a `private` or `internal` top-level type counts). Types nested inside another type, `companion object`s, `object :` expressions,
local classes inside functions and `Foo::class` are **not** top-level types.

**How it reads Kotlin.** Take comments (block comments **nest** in Kotlin, KDoc included), string literals (normal, raw `"""`,
templates with strings and braces inside such as `"${if (dark) "dark" else "light"}"`) and character literals (`'}'`, `'"'`, `'\''`)
out first, keeping line breaks so line numbers survive; then track brace depth and look for declarations only at depth 0, after
stripping annotations on the same or previous lines (`@Serializable`, `@RunWith(AndroidJUnit4::class)`, `@get:Rule`, with nested
parentheses) and modifiers. CRLF files exist in the tree; handle them.

**Allow-list.** The test carries `ALLOWED`, a path-keyed set (paths relative to the source root, with a `main/` or `test/` prefix) of exactly
the 14 files that still break the rule when this task lands, because the next Phase splits them:
`main/navigation/Destinations.kt`, `main/data/media/PhotoSource.kt`, `main/data/photo/PhotoLoader.kt`, `main/data/photo/PhotoSaver.kt`,
`main/ui/permission/PermissionGate.kt`, `main/data/photo/UprightJpeg.kt`, `main/data/settings/SettingsStore.kt`,
`test/gallery/GalleryPermissionTest.kt`, `test/gallery/GalleryGridTest.kt`, `test/save/SaveTestSupport.kt`,
`test/settings/PickerNoAlphaTest.kt`, `test/screenshots/GalleryGridScreenshotTest.kt`, `test/tool/ToolFixtures.kt`,
`test/settings/ScreenPixels.kt`. A file on the list is not reported, **and the test also fails if a listed file no longer breaks the
rule** (a stale entry): that second check is what proves on the real tree that the scanner detects violations, and it forces the
list to be emptied exactly when the files are fixed. The Iteration empties `ALLOWED` in the next Phase; leave it as a
`private val ALLOWED: Set<String>` with a KDoc saying so.

**Self-checks on inline strings** (in the style of `KdocCoverageTest.the_checker_reports_declarations_without_kdoc`), no fixture
types outside the test class: reported — two top-level classes; a `private class` beside a class; an `@Serializable` key on its own
annotation line beside another type; a type in a file named otherwise; accepted — a sealed interface with nested `data object`
cases, an enum with entries and methods, a `companion object`, a top-level `val x = object : Runnable { … }`, a local class inside a
function, `Foo::class`, the word `class` in a comment / KDoc / string / raw string, `'}'`, a nested block comment, and
`"${a.map { "}" }}"`. Self-test sample sources are strings; any helper type is nested inside the test class (this file is itself scanned).
