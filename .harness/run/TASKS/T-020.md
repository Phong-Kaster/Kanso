## Description

Found by the Verifier's fresh-context audit (Iteration 7). DoD 2's Proof says: "Tapping each row changes the scheme on the `kanso-theme` node to that choice's scheme within 10 s of real time." `ThemeSwatchTest.choose` (around line 256) waits only until `appliedScheme().primary == primary`. So a tap that applied the right `primary` with, for example, the wrong light or dark scheme, or a scheme from another seed sharing that `primary`, would pass.

Make `choose` compare the applied scheme with the scheme of the choice in the same roles that criterion 1 compares: `primary`, `onPrimary`, `primaryContainer`, `secondary`, `tertiary`, `background` and `surface`. Read how `KansoBlueThemeTest` builds and compares its expected scheme and do the same. The expected scheme of each choice, in light mode, is what the app makes for it:
- Kanso blue: `seedColorScheme(KANSO_BLUE_SEED, dark = false)`.
- From wallpaper: the app's wallpaper scheme. Read `ui/theme/KansoTheme.kt` to see exactly how the app builds it (it uses `dynamicLightColorScheme(context)` on Android 12 and later). Build the expected value the same way in the test.
- Custom: `seedColorScheme(<the custom seed>, dark = false)`.

Keep what `choose` already checks: the "another scheme before the tap" guard, `awaitSavedThemeColour`, the 10-second wait, and the selected and not-selected rows. Wait until all seven roles match, then assert each one, so a failure names the role that differs. Keep the KDoc in plain English and update it to say what is compared now. Do not change any test's name.
