## Description

A `GalleryScreen(tool, ...)` that, when first shown, asks for the right photo permission through `rememberLauncherForActivityResult(RequestMultiplePermissions())` (no Accompanist): API 34+ `READ_MEDIA_IMAGES` + `READ_MEDIA_VISUAL_USER_SELECTED`, API 33 `READ_MEDIA_IMAGES`, API 32 and below `READ_EXTERNAL_STORAGE`. Never at launch. States: granted (full), partial (API 34, only VISUAL_USER_SELECTED: notice with a "share more" button that re-requests), refused (plain explanation + "Open settings" button starting `ACTION_APPLICATION_DETAILS_SETTINGS` for the app package; no auto re-request; the "already asked" flag survives `recreate()`). The permission gate is reusable (the camera reuses it with `CAMERA`). The granted body is a placeholder content area with a root test tag for now; T-004 fills it. Roborazzi picture of the refused state, light and dark (`12_gallery_refused_light.png`, `13_gallery_refused_dark.png`). Colours from the theme only; refused panel must scroll if text is long. Explain runtime permissions in Compose in KDoc/comments.

Orchestrator wires before dispatch: `Gallery(tool)` key, five tools routed to it, `GalleryViewModel` Koin binding, manifest permissions, strings (Worker may use `R.string.gallery_*` keys the Brief lists).
