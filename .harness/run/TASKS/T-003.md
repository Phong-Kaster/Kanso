## Description

After this task the Saved screen has `SavedScreen.kt`, `SavedViewModel.kt` and `SavedUiState.kt`, and the photo decode
that `SavedScreen` does today with `koinInject<PhotoLoader>()` and `produceState` happens in the ViewModel instead.

- `SavedPhoto` (today `internal sealed interface` inside `SavedScreen.kt`) moves word for word into `SavedPhoto.kt` and becomes **public**.
- `SavedUiState.kt`: `data class SavedUiState(val photoUri: String, val photo: SavedPhoto = SavedPhoto.Loading)`. Its KDoc says what
  this screen's snapshot holds and points to `HomeUiState` for the explanation of the pattern (another task writes it; do not repeat it).
- `SavedViewModel(photoUri: String, loader: PhotoLoader, probe: ViewModelClearedProbe)`: one private `MutableStateFlow`
  exposed as `val state: StateFlow<SavedUiState>`, and `fun load(maxEdgePx: Int)` that works like `ToolViewModel.load`: it ignores a
  repeated request for the same size, cancels a load that is no longer wanted, and ends `Ready(bitmap)` or `Unreadable`.
  **No dispatcher hop of its own** (`PhotoLoader` already moves its work to IO, `PhotoLoader.kt:78`): add none. The probe
  records clearing like its siblings (`HomeViewModel`, `GalleryViewModel`, `CameraViewModel`, `ToolViewModel`). It takes no
  `tool`: nothing on this screen reads it (`SavedScreen`'s `tool` parameter is unused today); drop that parameter.
- `SavedScreen(viewModel: SavedViewModel, onShare, onEditAnother, onHome, modifier)` collects `state` and calls
  `LaunchedEffect(viewModel, maxEdgePx) { viewModel.load(maxEdgePx) }` with the same `maxEdgePx` the screen computes today.
  `SavedContent(state: SavedUiState, sharing: Boolean, onShare, onEditAnother, onHome, modifier)`. The **share block stays in the
  composable, unchanged**: its scope, the `sharing` flag, `shareableUri`, the chooser and `startActivity` (the share lookup needs
  the Activity's context and the test asserts the share intent's package, component and flags). `SavedPreview` keeps its name and
  builds a `SavedUiState` from `sampleBitmap()`; the file keeps its light and dark preview. `sampleBitmap()`/`samplePhoto()`
  stay private in `SavedScreen.kt` (preview sample data).
- Tests: `SavedScreenTest` and `SavedScreenshotTest` build `SavedViewModel(uri, FakePhotoLoader(…, ToolFixtures.gradient(600, 400)), ViewModelClearedProbe())`
  **before** `setContent` (lint forbids building a ViewModel inside a composable) and pass it in; they keep every test name,
  assertion and baseline name (`18_saved_light`, `19_saved_dark`). Their waits add `shadowOf(Looper.getMainLooper()).idle()`
  inside `waitUntil` (PROJECT.md: a ViewModel load awaited by a Robolectric Compose test needs it; this strengthens the wait).
- New `T/saved/SavedViewModelTest.kt` (Robolectric, because `FakePhotoLoader` needs a Context and a Bitmap): starts as Loading;
  becomes Ready with the bitmap when the loader returns one; becomes Unreadable when `FakePhotoLoader(app, null)` returns null;
  a second `load` with the same size does not call the loader again.
