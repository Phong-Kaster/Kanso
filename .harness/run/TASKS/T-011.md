## Description

Filed by the Verifier (Iteration 10). The first fresh full `./gradlew :app:testDebugUnitTest --rerun-tasks` on the finished tree (0b46878) failed: 198 tests, 1 failed. DoD 8's one allowed rerun covers only the `ThemeColourSettingsTest` flake, so DoD 8 and 13 are not proved. The same test failed once in Iteration 7 and twice during T-010; the following `verifyRoborazziDebug` run in Iteration 10 passed it, so it is intermittent.

```
java.lang.AssertionError: Retake left the shot's file behind
	at com.phongkaster.kanso.camera.CameraScreenTest.retake_deletes_the_shot_and_shows_the_shutter_again(CameraScreenTest.kt:119)
```

Likely cause (not yet proved): `CameraViewModel.retake()` calls `shot.delete()` on the main thread and ignores its result. `ShotView` (`AsyncImage(model = shot)`, Coil) may still hold the file open on a background thread while it decodes it; on Windows a file that is open cannot be deleted, so `delete()` returns false and the file stays. On a phone the same race cannot leave a file behind (Linux deletes open files), but the shot would still be left behind if the delete failed for another reason.

Make retake surely remove the file before the screen shows the shutter again, for example: delete, and on failure retry briefly (bounded, as `RetryingMoveFileSystem` does in T-010), or remove the shot from the state first so Coil lets go, then delete with a bounded retry before the shutter is enabled. The live picture and shutter must still come back at once on a phone. **Never** change an existing test (DoD 8). Keep the KDoc of `retake()` true.
