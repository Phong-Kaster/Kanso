## Description

Found by the Verifier's fresh-context audit (Iteration 7). DoD 4's Proof says that with the 600x400 `ToolFixtures.gradient` photo, "the photo fills its area (its width equals the area's width, or its height equals the area's height, within 1 px)". The test that loads that photo, `the_photo_the_panel_and_the_toolbar_stack_from_top_to_bottom` (around lines 316-332), checks only that the photo lies inside its area (`assertInside(image, body)`). The fill check exists only in another test (around lines 162-166), on a 400x200 EXIF-rotated JPEG.

Add the fill assertion to the gradient test, after `assertInside(image, body)`, in the same form and with the same failure message as lines 162-166:

    assertTrue(
        "The photo $image does not fill $body on either side",
        kotlin.math.abs(image.width - body.width) <= 1f ||
            kotlin.math.abs(image.height - body.height) <= 1f,
    )

Then update the test's KDoc ("...the toolbar inside the window and the photo inside its area") so it also says the photo fills the area on one side. Change nothing else.

## Acceptance

`./gradlew :app:testDebugUnitTest --tests '*ToolScreenTest*'` exits 0 with the new assertion. All tests stay green. The Iteration adds a line for this edit to the `ToolScreenTest.kt` row of `test-edits.md`.
