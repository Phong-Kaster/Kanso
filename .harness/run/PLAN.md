## Strategy

**Re-cut at Iteration 2 (2026-10-12), after D-001 was answered:** the owner approved the DoD with one edit, every tool one tap from Home with no swipe (A-001 reversed). Home's two pill buttons became a row of five round tool shortcuts. Only T-005 (the row), T-008 (the reach proof and the budget) and the tests that reach a tool gallery through Home (`HomeTaps`) change; T-001 (only a stale assumption id), T-002, T-003 (only the visible 48 dp circle of `RoundIconButton`), T-004, T-006 to T-011 (T-011 only says how case (a) taps Retouch's "Try now") and the phase order are untouched, and so is the list of 41 pictures. The first plan's text below is kept; where it says "pills" read "the five shortcuts".

Eleven tasks in four Phases, built on a clean base (`a720960`: 368 tests, 24 baselines, Material3 1.5.0-beta01 in the app, Run 6's Expressive look). The first plan had ten tasks; its critique and conflict analysis (Iteration 1) split Home in two, merged the gallery and camera restyles, split the cross-screen proofs in two, and moved every "this tab reaches that screen" assertion to the task that owns the screen, so no task's tests depend on a same-Phase task's files.

- **Order of attack.** The navigation shell comes first (T-001: three tab keys, the floating bar and its shell, the tab fade, back-stack helpers) because every other screen is reached through it and the old tests tap Home's Settings and Camera text. The saved-photo data source and the My edits tab (T-002) and the per-tool screen with its blurred backdrop (T-003, which deletes the five-tool toolbar) need nothing from the shell, so they share Phase 1. Phase 2 builds what needs them: Saved and the My edits viewer (T-004), Home's title, carousel and five round tool shortcuts (T-005) and the gallery and camera restyle (T-006). Phase 3: Settings rows (T-007), Home's Recent edits strip with skeletons and the one-tap reach proof (T-008) and the hex fix (T-009). Phase 4 is the cross-screen proofs (T-010, T-011) against the final screens.
- **Every task is a checkpoint.** After the Workers report, the Iteration wires the shared files, builds and runs the whole suite, runs `compareRoborazziDebug`, copies each changed comparison picture into `.harness/run/evidence/baseline-diffs/phase<N>/`, re-records the approved baselines with `foreman-record-baselines.ps1`, opens and judges every picture, runs the fresh-context review and commits once.
- **Verification set per Iteration** (named so "everything I ran passed" means something): `cleanTestDebugUnitTest testDebugUnitTest verifyRoborazziDebug lintDebug assembleDebug --continue` (covers main, unit tests, screenshots, lint, the APK), plus `:core:colorpicker:assembleDebug :core:colorpicker:assembleRelease` in Phase 3 (the one engine edit). Every Gradle command runs under `timeout`, writes to `.harness/run/evidence/`, and starts with `cd /d/Valve/Personal/Kanso &&`.
- **Baselines** (exact names below; D-001 lists the same). Phase 1 re-records 1-6, 24, 25 (the bar; Settings without Back), 16, 17, 22, 23 (tool screens) and records the new 28-33 and 40-42. Phase 2 re-records 1, 2, 3 (Home's new look), 10-13, 26, 27 (gallery), 18, 19 (Saved), 14, 15, 20, 21 (camera) and records 43, 44. Phase 3 re-records 1, 2, 3 (the strip), 4, 5, 6, 24, 25 (Settings rows) and records 34-39. A picture first recorded in one Phase counts as existing in the next; one that moves twice is re-recorded twice, each time with its compare file.
- **Strings.** Workers add new names only, in a new `res/values/strings_<area>.xml` of their task, and every name starts with its area prefix (`tab_`, `my_edits_`, `tool_screen_`, `saved_layout_`, `home_hero_`, `gallery_layout_`, `settings_rows_`) so two Workers never define one name: resources of all files merge into one namespace. A string a Worker adds must be used (DoD R9). No existing string is moved, renamed or removed by a Worker; only the Iteration removes strings (R9).
- **Tests, one rule.** Each Android version is its own `@Test` (as `LaunchTest` does); never one `@Test` under `@Config(sdk = [27, 30, 35])`, because DoD 35 compares the number of tests run with the number of `@Test` lines.
- **Whole-app tests that need Home's photo source** swap it BEFORE `ActivityScenario.launch(MainActivity::class.java)` with `loadKoinModules(module { single<SavedPhotoSource> { fake } })` (the Application has started Koin by then) and use `createEmptyComposeRule()`: Home's ViewModel is built when Home first draws, so a swap after launch never reaches it.
- **The floating bar overlays the tab screens**, so `performScrollTo()` followed by `performClick()` can land on the bar at a 320x470 dp test screen. Whole-app tests tap a node on a tab screen through `TabTaps.tapAboveBar()` (`performScrollTo()` then the semantics `OnClick` action); a test that proves a position uses real touch input only where the position is the point.
- **Shared files** (no Worker touches them; the Iteration edits them after the Workers report): `M navigation/KansoNavHost.kt`, `M navigation/Tool.kt`, `M navigation/KansoTransitions.kt` (untouched: the tab fade lives in a new file), `M di/AppModule.kt`, `R values/strings.xml`, `R values/strings_home.xml` (R9 removals), both `colors.xml`, `AndroidManifest.xml`, `build.gradle.kts` and the catalog, every drawable, `T previews/PreviewsRenderTest.kt` (`requiredPreviewNames`), `T previews/PreviewCoverageTest.kt`, `T ScreenStateTest.kt`, `T a11y/AccessibilityWalkTest.kt` and `T theme/ThemeFollowTest.kt` (the Iteration fixes their call sites AND the premises that break - see "Premises" below - in Phases 1 to 3; T-010 owns them after), every baseline PNG, `docs/adr/*`.
- **Back-stack logic is testable on its own.** T-001 puts every back-stack move (select a tab, replace a tool with its gallery, close to Home) in plain functions in `M navigation/BackStackActions.kt` with a unit test, and the shell composable and the tab fade in their own files with previews and tests, so the Iteration's wiring of `KansoNavHost.kt` is one call per callback.
- **Preview rules for the new files.** Every file with a composable carries its previews. `PreviewCoverageTest` counts a composable as covered only when a preview in the same file reaches it, and its list of exempt composables stays at three: so `ProvideSkeletonPulse(pulsing: Boolean = true, ...)` is reached by a still preview with `pulsing = false`, and `KansoTabBarPreview` calls `tabBarClearance()`. Screens take their thumbnails through a slot with a coloured stand-in in previews (`GalleryContent` shows the pattern at `GalleryScreen.kt:271-272, 827-862`); a preview never loads a real Uri.
- **Premises the Iteration fixes in the shared walk tests** (they break at run time, not only at compile time): Phase 1: `ThemeFollowTest.checkEditor` (the band of plain background above the photo is now the backdrop) and `checkSettings` (no top bar); Phase 2: `checkSaved` (the photo no longer leaves background beside the mark) and `checkHome` (a full-width carousel may cover the left-edge pixel); Phase 3: `checkHome`/`checkSettings` again if the strip or the rows move a sampled pixel.
- **Evidence helpers.** `.harness/run/evidence/testnames.sh` (the DoD 35 name list), the `base-*` files (made at bootstrap) and later `test-edits.md`, `m3-scan.md`, `fixed-colours.md`, `home-reach.md`, `orphans.sh`, `symbols/SOURCES.md`, `baseline-diffs/`.

## Known Risks

- **Every whole-app test now passes through a loading state at launch** once Home reads Recent edits (Phase 3). A pulse on `rememberInfiniteTransition` may keep `waitForIdle()` from returning (PROJECT.md). Mitigation: the phase is static by default (`LocalSkeletonPhase`), animated only by the stateful screens; the Phase 1 spike tells early; whole-app fakes finish within a frame as before; every Gradle run is under `timeout`.
- **The carousel is lazy** (`HorizontalUncontainedCarousel` composes only the banners in view): a test that wants the "Try now" of Enhance, Retouch or Artistic must swipe to it. Since D-001 no other test needs the carousel: `HomeTaps.openToolGallery` taps the tool's `home-shortcut-<TOOL>` (always composed, one tap), so a swipe is needed only where a test names a banner or its "Try now": `HomeScreenTest` (DoD 4, 28), `PhotoToToolNavigationTest` (DoD 5), `NavigationTest` (DoD 21, "each Try now"), `ReplaceNavigationTest` (DoD 11(a), Retouch's "Try now"), `ThemeFollowTest` (DoD 23, each banner's colour) and `AccessibilityWalkTest` (DoD 25, the carousel on each banner).
- **The fits-without-scrolling budget** is 24 dp spare at a 48 dp navigation bar on 360x780 dp with the row heights above (re-cut by D-001: five shortcuts of 84 dp instead of pills of 48 dp, paid for by a 176 dp carousel and 12 dp gaps); the carousel is the only row that may shrink, to 160. If `HomeReachTest` shows less than 8 dp spare, T-008 shrinks the carousel before touching anything else.
- **Five names on 65 dp columns.** "Remove background" is two `labelSmall` lines on 360 dp (about 65 dp a column) and may wrap by letters on the 320 dp default test screen; no criterion reads the label's line count at 320 dp, `HomeReachTest` and the pictures use 360 dp and wider.
- **`Modifier.blur` draws nothing in Robolectric's software capture and below Android 12.** The backdrop is a stretched tiny copy on every API with `blur` on top, so a pixel test can assert softness without the blur.
- **The Settings text is on screen twice** (title and tab): tests find tabs by tag and role, never `onNodeWithText("Settings")`.
- **A tab fade is a push to NavDisplay** (replacing the top key is not a prefix pop): per-entry `transitionSpec` metadata returns a fade only when both scenes are tabs and null otherwise, so the predictive-back tests (which build their own NavDisplay) stay untouched; `NavTransitionTest` gains a tab case.
- **Whether `ComposeUiTest`'s infinite-animation policy cancels `rememberInfiniteTransition`** is unconfirmed (the sources are not here); the spike answers it.
- **Permissions.** Android 8.1/9 cannot read `Pictures/Kanso` without the photo-read permission; Home and My edits never ask, so on those phones, and after a reinstall on Android 10+, the empty message shows (Q11). A real MediaStore query is not drivable under Robolectric: a recording provider (an in-memory table that applies the selection and the sort and takes inserts) proves it, a person proves it on the phone.
- **Guard tests.** `ScreenStateTest` needs every screen package's three files; `KdocCoverageTest` reads line by line; `OneTypePerFileTest` scans test files too (`RecordingMediaProvider` and every fake in its own file).
- **Flakes.** `ThemeColourSettingsTest` and `CameraScreenTest.retake_...` flaked on Windows before; Phase 4 ends with three fresh full runs.
- **Unprovable by machine**: the blur on a real GPU, the carousel's feel, the motion and "Remove animations", the back gesture handoff, the InFlux likeness (criteria 20, 27-31).
