# Artistic (T-006): how the tool is built

- Files: `data/edit/artistic/` `ArtisticStyle` (enum: WARM_WASH, COOL_WASH, MOSAIC, INK; `id`, `nameRes`, `assetPath = "styles/<id>.webp"`), `Stylizer` (interface, full-strength paint), `EngineStylizer` (only file naming `com.photo.editor.localml.styletransfer.*`), `ArtisticProcessor` (ToolProcessor), `StyleImages` (draws each style image, 256x256, seeded `Random(style.ordinal)`, deterministic). UI: `ui/tool/ArtisticPanel.kt` (`ArtisticPanel` stateless, `ArtisticPanelHost(onApply: (ArtisticStyle, Float) -> Unit, modifier, enabled)` stateful, tags `ARTISTIC_PANEL_TAG` (from ToolPanel.kt), `ARTISTIC_STRENGTH_TAG`, `ARTISTIC_RUN_TAG`, `artisticStyleTag(style)` = `"artistic-style-" + id`). Strings: `res/values/strings_artistic.xml` (`artistic_*`).
- Engine call: `StyleTransferInceptionV3BlendUC(app, StylePredictInceptionV3UC(app))`, `coroutineScope { initModel(this)?.join() }`, then `invoke(photo, styleBitmap, FULL_STYLE_RATIO)`. `FULL_STYLE_RATIO = 1f` is UNVERIFIED (which end is full style); flip it in `EngineStylizer.FULL_STYLE_RATIO` only, after the device run (DoD 13). `?.join()` is used because the javap facts did not say whether `initModel` returns `Job` or `Job?` (a needless `?.` is only a warning).
- Style image: `EngineStylizer.readStyleImage(context, style)` decodes `assets/styles/<id>.webp`; on `IOException` or a null decode it falls back to `StyleImages.draw(style)`. The Iteration exports `StyleImages.draw` to those asset files (Workers cannot write binaries); export must be lossless or near-lossless to keep "exported == fallback" meaningful.
- Processor: fit to 1024 (`WorkingSize.ARTISTIC`), paint with the stylizer, cache the last `(input bitmap identity, style) -> (working copy, painted)`; a run with the same input object and style but another strength skips the stylizer. Mix per pixel in Kotlin `o + s*(p - o)` (s clamped 0..1), alpha forced 0xFF, `setHasAlpha(false)`. Painted picture of another size is `createScaledBitmap`-ed to the working copy. Progress 0, 0.9 after painting, 1. The settings (`style`, `strength`) are `@Volatile var`s set before `process`.
- The ViewModel must pass the SAME input bitmap (the photo before Artistic, not the last Artistic result) on slider moves, or the cache misses and the model reruns.
- Not verified: whether the engine's `invoke` modifies the photo it is given (it is handed the working copy, which is the caller's input itself when the photo is already <= 1024 px).
