# T-002 design (Iteration 3 decision; copy into every Worker Brief)

Paths: M/ = app/src/main/java/com/phongkaster/kanso/, T/ = app/src/test/java/com/phongkaster/kanso/.

EditSettings (data/edit/edit): ONE crop rectangle `crop: CropRect = CropRect.FULL` (replaces freeCrop) for every ratio; `cropRatio: CropRatio? = null` only LOCKS the shape of the handles (null/FREE = unlocked). Sliders stay Float -1..1 (UI shows x100), filterIntensity 0..1 default 1f, filter default NONE. Keep CropRect and constants. Helpers: `val isNeutral: Boolean` (== EditSettings()), `fun isNeutral(tool: EditTool): Boolean` (CROP: crop==FULL; ROTATE: quarterTurns%4==0 && no flips; ADJUST: !hasColourChange; FILTERS: !hasFilter). Rewrite the KDoc: no more "one change"/"apply in order crop,turn,flip,colour,filter".

EditProcessor(settings, filters): renders the WHOLE settings against the ORIGINAL it is given. Order: crop (always from settings.crop; a fixed ratio is just a rectangle now), turn, flip, FILTER, then colour matrix (A-002: filter before sliders). `colourMatrix` becomes `internal` (companion). Drop the cropBounds fixed-ratio branch. Fix KDoc.

EditSession (new, data/edit/edit/EditSession.kt): immutable data class `EditSession(settings: EditSettings = EditSettings(), undoStack: List<EditSettings> = emptyList(), pending: EditSettings? = null)`. `canUndo` = undoStack non-empty. `change(new)`: an ACTION (chip, turn, flip, crop done): if new == settings return this, else push settings onto undoStack, settings=new, pending=null. `preview(new)`: mid-gesture (slider dragging): remembers pending = pending ?: settings, settings = new, no undo push. `commit()`: if pending != null: if pending != settings push pending, then pending=null. `undo()`: pops one entry into settings (pending=null); returns this if empty. A slider release, a filter chip, a crop and a quarter turn are one undo entry each. `cropRatioChosen(ratio, photoAspect: Float)`: an action setting cropRatio=ratio and crop = centred rectangle of that shape fitted inside a photo with width/height = photoAspect (FREE/null => crop unchanged, cropRatio set accordingly; use CropRatio.widthPart/heightPart). Pure Kotlin, no Android.

ToolUiState (ui/tool): add `settings: EditSettings = EditSettings()` (the session's current settings), `discardPrompt: Boolean = false`. Keep canUndo, openTool, comparing, edited, processing. (UiState may hold no var / Mutable*.)

ToolViewModel: holds `private var session = EditSession()`. New API:
 - `changeSettings(new: EditSettings, processorFor: (EditSettings) -> ToolProcessor)` = action: session.change(new), publish state.settings/canUndo, re-render.
 - `previewSettings(new, processorFor)` = mid-drag: session.preview(new), publish, re-render.
 - `commitSettings()` = slider released: session.commit(), publish canUndo.
 - `undo()` pops one session action, publishes, re-renders with the last processorFor given (remember it); with the stack empty does nothing. Still does nothing while comparing.
 - rendering: each render runs `processorFor(settings).process(fittedOriginal)` from the ORIGINAL (cached fit, WorkingSize.maxEdgeFor(tool)) off the main thread (workDispatcher); a new render CANCELS the previous one and the LATEST settings always win (a release during a render is never dropped; no "ignore while running"). Result -> state.edited (null when settings are neutral, so Save writes the original); failure -> state.failure. Generation counter so a cancelled/stale render never overwrites state or sets processing Idle.
 - the old apply()/history path stays ONLY for the other tools (Retouch, Artistic, ...): do not break them; remove only what Edit used (the `edited ?: original` stacking for Edit).
 - `onBackPressed(): Boolean` (Edit screen only): if openTool != null -> closeTool(), true; else if !settings.isNeutral -> discardPrompt=true, true; else false (caller leaves). `dismissDiscardPrompt()` (Keep editing). `confirmDiscard()` clears prompt (caller then leaves).
 - openTool/closeTool/setComparing/save unchanged. save() saves state.edited if non-null.

EditPanel (ui/tool): `EditPanel(openTool, settings: EditSettings, photoAspect: Float, onChange: (EditSettings, (EditSettings) -> ToolProcessor) -> Unit, onPreview: (EditSettings, (EditSettings) -> ToolProcessor) -> Unit, onCommit: () -> Unit, onRatio: (CropRatio, Float, (EditSettings)->ToolProcessor) -> Unit (or equivalent), modifier, enabled, filterSource)` — it owns the FilterLut source and builds `{ s -> EditProcessor(s, filters) }`. NO local settings state: everything it draws comes from `settings`, so the sheet being recreated by AnimatedContent loses nothing. Adjust: four sliders -100..100 shown as integers beside the name (e.g. "Brightness 70"), centre 0, never spring back; drag -> onPreview, release -> onCommit. Filters: chips None + 7 presets, one at a time (selected chip = settings.filter), None = filter NONE; choosing a preset from None sets filterIntensity 1f; intensity slider 0..100 shown beside its name, drag -> onPreview, release -> onCommit; a chip tap is one action via onChange. Rotate: turn left, turn right, flip across (horizontal), flip upside down (vertical): each one action. Crop: ratio chips (fixed ratio sets a centred rectangle and locks; Free unlocks); the free-crop range sliders and "Crop" apply button may stay but edit settings.crop (T-004 replaces them with handles). EditPanelContent stays stateless. Keep existing test tags; add `EDIT_SLIDER_VALUE` text via normal Text. Every composable keeps a light+dark preview.
EditToolRow: each entry shows a small dot (tag `edit-tool-dot-<TOOL>`) when its settings are not neutral (EditSettings.isNeutral(tool)); EditToolContent passes `state.settings`. EditToolContent: keep the 60/40 layout.
DiscardChangesDialog (ui/tool): stateless `DiscardChangesDialog(onDiscard, onKeepEditing)`, Material3 AlertDialog, title "Discard your changes?", buttons "Discard" and "Keep editing", tags `discard-dialog`, `discard-confirm`, `discard-keep`; preview light+dark.
Strings: only in new res/values/strings_edit_session.xml, names prefixed `edit_session_`; use every one. ToolScreen.kt and AppModule are NOT in your scope: the Iteration wires them.
